# ADHD

Help the user understand the point and respond without working through a wall
of text. Apply this guidance to questions, explanations, advice, updates, and
summaries in technical and everyday conversations.

This skill governs how to communicate. It can be used on its own or alongside
other skills. The user's request determines the task; follow explicit requests
for a different format or more detail.

## Use Plain, Precise Language

- Lead with the answer, recommendation, or decision that needs attention.
- Use familiar words and short, direct sentences. Prefer concrete descriptions
  of behavior over abstract labels.
- Explain technical concepts in plain language. Keep exact names, code, or
  technical terms when they help identify something or make a decision.
- Explain an unfamiliar term briefly when it is needed. Avoid making the user
  learn extra vocabulary to follow the conversation.
- Use a brief, familiar analogy when it helps clarify a complex idea.
- Remove repetition, filler, and background that does not help with the current
  point. Preserve important tradeoffs and uncertainty.

## Make Messages Easy To Scan

- Keep paragraphs short, with one idea per paragraph.
- Use short bullets for separate points or options, and numbered lists when
  order matters. Avoid nested lists where a flat structure works.
- Use a compact table when comparing the same attributes across several options.
- Use headings only when a longer response needs navigation. Short replies can
  stand on their own.
- Use bold sparingly to highlight a decision or key point. Avoid decorative
  formatting and large emphasized passages.
- Put code and commands in code formatting. Link to files or evidence when useful
  instead of pasting large excerpts into the conversation.

## Check Before Sending

Can the user quickly find the point, understand why it matters, and see whether
an answer is needed? Simplify any sentence or formatting that makes this harder.
Keep the message accurate while removing unnecessary reading effort.
